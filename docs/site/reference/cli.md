## llmkube benchmark

Benchmark an LLM inference service

```text
Run performance benchmarks against a deployed LLM inference service.

This command sends test requests to the inference endpoint and measures:
- Prompt processing speed (tokens/sec)
- Generation speed (tokens/sec)
- Latency percentiles (P50, P95, P99)
- Request success rate

SINGLE SERVICE MODE:
  Benchmark an already-deployed inference service.

STRESS TEST MODE (--concurrent or --duration):
  Run concurrent requests to stress test the service. Automatically uses varied
  prompts (short, medium, long) to stress both prompt processing and generation.

CATALOG MODE (--catalog):
  Automatically deploy, benchmark, and compare multiple models from the catalog.
  Models are deployed sequentially, benchmarked, and optionally cleaned up.

TEST SUITES (--suite):
  Run predefined comprehensive test suites. Requires --catalog for model deployment.

  Available suites:
    quick     Fast validation (~10 min)
              • Concurrent load test (1,2,4 workers, 2min each)
              • Quick stress test (4 workers, 5min)

    stress    Stress focused (~1 hr)
              • Preload model cache
              • Concurrency sweep (1,2,4,8 workers, 5min each)
              • Stability test (4 workers, 30min)

    full      Comprehensive (~4 hr)
              • Preload model cache
              • Concurrency sweep (1,2,4,8 workers)
              • Token generation sweep (64-2048 tokens)
              • Context size sweep (4K-32K, redeploys)
              • Stability test (4 workers, 1hr)

    context   Context length testing
              • Context sweep (4K, 8K, 16K, 32K, 64K)

    scaling   Multi-GPU efficiency
              • Single GPU baseline (1,2,4 workers)
              • Multi-GPU comparison (1,2,4 workers)

SWEEP MODES:
  Test across multiple configurations automatically:
  --concurrency-sweep: Test multiple concurrency levels (e.g., 1,2,4,8)
  --context-sweep:     Test multiple context sizes (e.g., 4096,16384,32768)
  --tokens-sweep:      Test multiple generation lengths (e.g., 64,256,512)

REPORTING:
  Generate markdown reports with --report or --report-dir for analysis and sharing.

AUTHENTICATION:
  A service whose InferenceService sets spec.endpoint.apiKeySecretRef is
  benchmarked with that key: the CLI reads the Secret through your kubeconfig
  and sends "Authorization: Bearer <key>". Override it with --api-key-file or
  LLMKUBE_API_KEY, which win over the ref and are required when the key cannot
  be read (an --api-key in spec.extraArgs, or a service outside Kubernetes).
  An --endpoint run never reads the cluster, and --api-key-file and
  LLMKUBE_API_KEY apply to it like to any other run: an exported variable is
  sent to whatever URL you point --endpoint at, so scope it to the run.
  The key is never printed. Reading the Secret needs "get secrets" in the
  service's namespace.
  Whitespace a header cannot carry is stripped: a Secret or a variable that
  needed it says so, --api-key-file is trimmed at both ends silently, and a
  variable holding only whitespace counts as unset, so the ref applies.

Examples:
  # Basic benchmark (sequential requests)
  llmkube benchmark my-llm -n default

  # TEST SUITE: Quick validation
  llmkube benchmark --suite quick --catalog llama-3.2-3b --gpu

  # TEST SUITE: Full comprehensive test with report
  llmkube benchmark --suite full --catalog qwen-2.5-32b --gpu --gpu-count 2 --report-dir ./reports

  # TEST SUITE: Stress test with preloading
  llmkube benchmark --suite stress --catalog mistral-7b --gpu --report stress-report.md

  # STRESS TEST: 8 concurrent requests for 30 minutes
  llmkube benchmark my-llm --concurrent 8 --duration 30m

  # STRESS TEST with report
  llmkube benchmark my-llm --concurrent 4 --duration 1h --report stress-test.md

  # Concurrency sweep - test scaling with report
  llmkube benchmark my-llm --concurrency-sweep 1,2,4,8 --duration 5m --report-dir ./reports

  # Context sweep - test different KV cache sizes
  llmkube benchmark --catalog qwen-2.5-32b --context-sweep 4096,16384,32768 --gpu

  # CATALOG MODE: Full report with preloading
  llmkube benchmark --catalog llama-3.2-3b,phi-4-mini --gpu --preload --report comparison.md
```

**Usage**

```text
llmkube benchmark [SERVICE_NAME] [flags]
```

**Flags**

```text
      --accelerator string          Hardware accelerator: cuda, metal, rocm, intel (auto-detected if --gpu is set)
      --api-key-file string         File holding the endpoint API key (default: the InferenceService's endpoint.apiKeySecretRef)
      --catalog string              Comma-separated list of catalog model IDs to benchmark
      --cleanup                     Cleanup deployments after benchmarking (use --no-cleanup to keep) (default true)
      --concurrency-sweep string    Test multiple concurrency levels (comma-separated, e.g., 1,2,4,8)
  -c, --concurrent int              Number of concurrent requests for stress testing (default 1)
      --context int32               Context size (KV cache) for model deployment (0 = use catalog default)
      --context-sweep string        Test multiple context sizes (comma-separated, e.g., 4096,8192,16384)
      --deploy-wait duration        Timeout waiting for deployment to be ready (default 10m0s)
      --duration duration           Run stress test for specified duration (e.g., 30m, 2h)
      --endpoint string             Benchmark this URL instead of looking the service up (SERVICE_NAME may be omitted)
      --gpu                         Enable GPU acceleration for catalog deployments
      --gpu-count int32             Number of GPUs per pod (for multi-GPU benchmarks) (default 1)
      --gpu-layers int32            Number of model layers to offload to GPU (-1 = use catalog default) (default -1)
  -i, --iterations int              Number of benchmark iterations (default 10)
      --max-tokens int              Maximum tokens to generate per request (default 50)
      --monitor-gpu                 Monitor GPU memory usage during benchmark (requires nvidia-smi)
  -n, --namespace string            Kubernetes namespace (default "default")
  -o, --output string               Output format: table, json, markdown (default "table")
      --port-forward                Automatically set up port forwarding (default true)
      --preload                     Preload model cache before benchmarking (catalog mode only)
  -p, --prompt string               Prompt to use for benchmarking (default "Explain what machine learning is in exactly three sentences.")
      --prompt-depth-sweep string   Test multiple prompt depths against a single deployment (comma-separated, e.g., 512,2048,8192)
      --prompt-file string          Load prompts from file (one per line) for varied workload
      --report string               Generate markdown report to specified file path
      --report-dir string           Directory for auto-timestamped reports (creates benchmark-YYYYMMDD-HHMMSS.md)
      --suite string                Run predefined test suite: quick, stress, full, context, scaling (requires --catalog)
      --timeout duration            Request timeout (default 1m0s)
      --tokens-sweep string         Test multiple max-token values (comma-separated, e.g., 64,256,512,1024)
      --warmup int                  Number of warmup requests (not counted) (default 2)
```

### llmkube cache clear

Clear cached models

```text
Remove entries from the persistent model cache.

Entries are removed through a short-lived pod that mounts the cache claim
read-write; the controller does not mount it. That pod runs busybox:1.37.0
unless --cache-image or LLMKUBE_CACHE_IMAGE names another image.

By default, clears every entry of the cache claims `cache list` discovers.
Use --model to clear a specific model's cache entry (which also reaches a
spec.modelCache.claimName its InferenceService brings), or --orphaned to
remove every entry no Model uses.

WARNING: Clearing the cache will cause models to be re-downloaded
when InferenceServices restart or new pods are created.

Examples:
  # Clear a specific model's cache entry
  llmkube cache clear --model llama-3.1-8b -n default

  # Remove every entry that no Model references
  llmkube cache clear --orphaned -n default

  # Clear all cache without confirmation
  llmkube cache clear --force -n default
```

**Usage**

```text
llmkube cache clear [flags]
```

**Flags**

```text
      --cache-image string   Image for the short-lived pod that mounts the cache claim (default busybox:1.37.0, or $LLMKUBE_CACHE_IMAGE)
      --force                Force clear without confirmation
      --model string         Clear cache for a specific model
  -n, --namespace string     Kubernetes namespace (default "default")
      --orphaned             Clear only orphaned cache entries (no matching Model)
```

See also [global flags](#global-flags).

### llmkube cache list

List cached models

```text
List all models in the persistent cache.

Shows cache entries with their size, status, and which Model resources
are using each cache entry. Each cache claim is read through a short-lived
read-only pod the command creates and deletes, so it works even when the
only other pod mounting the claim cannot run a shell. That pod runs
busybox:1.37.0 unless --cache-image or LLMKUBE_CACHE_IMAGE
names another image, which is what an air-gapped cluster needs. The command
fails when no discovered claim can be read, rather than reporting the cache
as empty; a claim that cannot be read while others can is skipped with a
warning.
```

**Usage**

```text
llmkube cache list [flags]
```

**Flags**

```text
  -A, --all-namespaces       List models from all namespaces
      --cache-image string   Image for the short-lived pod that reads the cache claim (default busybox:1.37.0, or $LLMKUBE_CACHE_IMAGE)
  -n, --namespace string     Kubernetes namespace (default "default")
      --orphaned             Show only orphaned cache entries (no matching Model)
```

See also [global flags](#global-flags).

### llmkube cache prep

Prepare a model cache directory for shared access

```text
Prepare a model cache directory for shared access by changing its
ownership and permissions via direct syscalls.

This command is intended to be used as the entrypoint of an init container
so that it retains its effective capabilities (CAP_CHOWN/CAP_FOWNER) without
an intermediate exec. It calls os.Chown and os.Chmod directly.

Examples:
  # Change ownership to root:102 and set group rwX
  llmkube cache prep --owner 0:102 --mode 0775 /models
```

**Usage**

```text
llmkube cache prep DIR [flags]
```

**Flags**

```text
      --mode string    Octal permission mode (e.g. 0775)
      --owner string   Owner in uid:gid format (e.g. 0:102)
```

## llmkube deploy

Deploy a local LLM inference service

```text
Deploy a local LLM inference service to Kubernetes.

This command creates both a Model resource (to download and manage the model)
and an InferenceService resource (to serve the model via an OpenAI-compatible API).

You can deploy models from the catalog (recommended) or provide a custom model URL.
For air-gapped environments, you can use local file paths or file:// URLs.

Examples:
  # Deploy from catalog (simplest - recommended!)
  llmkube deploy llama-3.1-8b --gpu
  llmkube deploy qwen-2.5-coder-7b --gpu

  # List available catalog models
  llmkube catalog list

  # Deploy catalog model with custom settings
  llmkube deploy llama-3.1-8b --gpu --replicas 3

  # Deploy custom model with URL
  llmkube deploy my-model --gpu \
    --source https://huggingface.co/.../model.gguf \
    --cpu 4 \
    --memory 8Gi \
    --gpu-layers 32

  # Air-gapped: Deploy from local file path
  llmkube deploy my-model --gpu \
    --source /mnt/models/llama-3.1-8b-q4_k_m.gguf

  # Air-gapped: Deploy from a PersistentVolumeClaim
  llmkube deploy my-model --gpu \
    --source pvc://my-models-pvc/llama-3.1-8b-q4_k_m.gguf

  # Deploy with SHA256 integrity verification
  llmkube deploy my-model --gpu \
    --source https://example.com/model.gguf \
    --sha256 abc123...

  # Air-gapped: Use catalog defaults with local model file
  llmkube deploy llama-3.1-8b --gpu \
    --source-override /mnt/models/llama-3.1-8b-q4_k_m.gguf
```

**Usage**

```text
llmkube deploy [MODEL_NAME] [flags]
```

**Flags**

```text
      --accelerator string        Hardware accelerator (cpu, metal, cuda, rocm, intel). With --gpu and no --accelerator: metal when the
                                  namespace has a Reachable MetalNode and no node advertises nvidia.com/gpu, cuda otherwise
      --args strings              Container args override (for generic runtime)
      --autoscale-metric string   Custom metric for autoscaling (default: llamacpp:requests_processing)
      --cache-type-k string       KV cache type for keys (f16, q8_0, q4_0, etc.). Maps to llama.cpp --cache-type-k.
      --cache-type-v string       KV cache type for values (f16, q8_0, q4_0, etc.). Maps to llama.cpp --cache-type-v.
      --command strings           Container entrypoint override (for generic runtime)
      --container-port int32      Override the container port (default depends on runtime)
      --context int32             Context window size in tokens (e.g., 8192, 16384, 32768). If not specified, uses llama.cpp default.
      --cpu string                CPU request (e.g., '2' or '2000m') (default "2")
      --env strings               Environment variables in KEY=VALUE format (can specify multiple times)
      --extra-args strings        Additional runtime arguments (can specify multiple times)
      --flash-attn                Enable flash attention for faster prompt processing and reduced VRAM usage. Requires NVIDIA Ampere or newer GPU.
      --format string             Model format (default "gguf")
      --from-cache                Deploy only from the model cache; fail if the model is not already cached
      --gpu                       Enable GPU acceleration
      --gpu-count int32           Number of GPUs per pod (default 1)
      --gpu-layers int32          Number of model layers to offload to GPU (-1 = all layers, 0 = auto) (default -1)
      --gpu-memory string         GPU memory footprint recorded on the InferenceService, e.g. '8Gi'. Not enforced (sets no pod resource request)
      --gpu-vendor string         GPU vendor (nvidia, amd, intel) (default "nvidia")
      --image string              Container image for the inference server. Default: the image the operator picks for the runtime and GPU
                                  (the chart's runtimeImages if set, else its pinned llama.cpp build), except
                                  ghcr.io/ggml-org/llama.cpp:server-intel for --gpu --accelerator intel. Required with --runtime generic.
                                  Use this to pin another build (e.g., ghcr.io/ggml-org/llama.cpp:server-cuda13 for CUDA 13).
      --jinja                     Enable Jinja2 template rendering for tool/function calling support.
      --max-replicas int32        Maximum replicas for autoscaling (enables HPA when set)
      --memory string             Memory request (e.g., '4Gi') (default "4Gi")
      --memory-budget string      Absolute memory budget for model inference (e.g., '24Gi', '8192Mi'). Only used with --accelerator metal. Takes precedence over --memory-fraction.
      --memory-fraction float     Fraction of system memory to budget for model inference (0.0-1.0). Only used with --accelerator metal. Overrides the agent default.
      --min-replicas int32        Minimum replicas for autoscaling (enables HPA when set with --max-replicas)
  -n, --namespace string          Kubernetes namespace (default "default")
      --node-port int32           Pin a stable NodePort (30000-32767) for the service. Sets the endpoint type to NodePort and pins this port. Default: auto-assign / ClusterIP.
      --parallel int32            Number of concurrent request slots (1-64). Enables parallel inference for multiple users.
  -q, --quantization string       Model quantization (e.g., Q4_K_M, Q8_0)
  -r, --replicas int32            Number of replicas (default 1)
      --runtime string            Inference runtime backend (llamacpp, vllm, sglang, generic) (default "llamacpp")
      --sha256 string             Expected SHA256 hash of the model file for integrity verification
      --skip-cache                Skip the model cache; force a fresh download even if the model is already cached
      --skip-model-init           Skip the model download init container (use when model is baked into image)
  -s, --source string             Model source URL or local path (GGUF format). Optional if using catalog model ID.
                                  Supports: https://, http://, file://, pvc://, or absolute paths (e.g., /mnt/models/model.gguf)
      --source-override string    Override the model source for catalog models with a local path (air-gapped deployments)
      --timeout duration          Timeout for waiting (default 10m0s)
  -w, --wait                      Wait for deployment to be ready (default true)
```

### llmkube fleet register

Register an edge site as a FederatedCluster

```text
Register a new edge site on the datacenter cluster.

This creates a FederatedCluster object plus a least-privilege ServiceAccount,
ClusterRole, and ClusterRoleBinding scoped to ONLY that one FederatedCluster's
status subresource. It then mints a token for that ServiceAccount and prints
an edge-config snippet (kubeconfig + operator flags) for the site admin to
install on the edge cluster's operator.

Run this against the DATACENTER cluster's kubeconfig context.
```

**Usage**

```text
llmkube fleet register [flags]
```

**Flags**


### llmkube foreman dispatch

Fan a batch of issues across coder agents and watch them run

```text
Create one AgenticTask per issue, round-robined across the named coder
Agents, then watch them all to completion and print a summary.

Round-robining across Agents bound to different boxes is what runs the batch

  # Two issues, one per box, watched to completion:
  llmkube foreman dispatch --repo defilantech/LLMKube \

  llmkube foreman dispatch --repo defilantech/LLMKube --agents coder-metal \

  llmkube foreman dispatch --repo defilantech/LLMKube --agents coder-go \
    --revise-from-branch foreman/adhoc/issue-991 \
```

### llmkube foreman slice

Plan an issue into disjoint slices and render a sliced Workload

```text
Render a sliced Workload and apply it, from either a pre-made plan or by
planning an issue.

The pipeline is one issue-fix step per disjoint slice, then an integrate step
that unions the slice branches, then a reconcile step that checks the union
against the plan's pinned shared identifiers, then a verify step that runs the

--verify-agent "" for non-code slicing).

  --plan FILE          render from a slice plan the planner already produced.
  ISSUE --planner-url  plan the issue with a model, then render.

  # Render a pre-made plan, dry-run:
  llmkube foreman slice --plan slice-plan-700.yaml --dry-run

  # Plan issue 700 with a local model, then apply:
  llmkube foreman slice 700 --repo defilantech/LLMKube \
    --planner-url http://localhost:18080 --planner-model ornith-35b \
    --repomap /tmp/repomap.txt --coder-agent coder-metal
```

**Usage**

```text
llmkube foreman slice [ISSUE] [flags]
```

**Flags**

```text
      --base-branch string       Base branch the slices are cut from and unioned onto (default "main")
      --coder-agent string       Agent that runs each slice's issue-fix step (default "coder-metal")
      --dry-run                  Print the rendered Workload without applying it
      --integrate-agent string   Deterministic agent that runs the integrate step (default "integrate")
      --namespace string         Namespace to create the Workload in (default "default")
      --plan string              Path to a slice plan YAML (skips planning)
      --planner-model string     Planner model name to send in the request
      --planner-token string     Bearer token sent to --planner-url; falls back to PLANNER_TOKEN env. Omit for direct InferenceService
      --planner-url string       OpenAI-compatible base URL of the planner model (required when planning an issue)
      --reconcile-agent string   Deterministic agent that runs the reconcile step (default "reconcile")
      --repo string              Target repo as owner/name (required when planning an issue)
      --repomap string           Path to a repository map file to give the planner
      --verify-agent string      Deterministic gate Agent that build+envtest-verifies the integrated branch after reconcile (must exist in the target namespace); empty string skips verify for non-code slicing (default "gate")
```

### llmkube metal join

Join this host to the cluster with a join string

```text
Set up the Metal agent on this host with the join string an admin created
with 'llmkube metal token create <name>'.

join trusts only the CA in the join string (no system roots) and prints its
pin: compare it with the pin token create printed. It then mints the agent's
own token for the host's ServiceAccount, writes it and a kubeconfig that reads
it (both 0600) under ~/Library/Application Support/llmkube/metal-agent,
deletes the join Secret so the string cannot be used again, installs and
starts the com.llmkube.metal-agent LaunchAgent, and waits until the cluster
reports the host's MetalNode Reachable.

The agent renews its token at half its lifetime (--token-lifetime, 7 days by
default). A host that is off for longer needs a new join string. Running join
again replaces the earlier setup; 'llmkube metal leave' removes it.

--host-ip and --allowlist set the agent's --host-ip and
--inference-service-allowlist, and --agent-arg <flag>=<value> (repeatable)
passes any other agent flag, such as --agent-arg port=9091. A re-join keeps
every agent argument the previous join's LaunchAgent has that join does not
set itself, hand edits included, and prints them; a flag given now replaces
a kept value, and an empty --host-ip or --allowlist drops it.

join refuses to replace a com.llmkube.metal-agent LaunchAgent it did not
write (make install-metal-agent, a playbook), since that one carries the
Mac's own arguments; --force replaces it, without its arguments, and keeps a
copy for leave to point back to.

Before it uses the join string, join refuses to run as root, checks that
this user is logged in at the Mac (a LaunchAgent runs only in a GUI login
session), and checks that the ports the agent binds (--port 9090 and
--client-port 9999 on 127.0.0.1, --ingress-port 9443) are free or held by the
agent it replaces.

On a Linux host (experimental), join writes the kubeconfig and token under
$XDG_DATA_HOME/llmkube/metal-agent (~/.local/share/...), installs the agent as
the llmkube-metal-agent.service systemd user unit in
$XDG_CONFIG_HOME/systemd/user (~/.config/...), and starts it with systemctl
--user. Instead of a GUI session it checks that this user's systemd instance
answers. Without lingering (loginctl enable-linger, which join only suggests)
the agent stops at logout and starts at the next login. Without llama-server,
join goes on when the agent's runtime is another one, such as
--agent-arg runtime=ollama.
```

**Usage**

```text
llmkube metal join <join-string> [flags]
```

**Flags**

```text
      --agent-arg stringArray     Another agent flag as <flag>=<value>, such as port=9091 (repeatable; not the flags join sets itself)
      --agent-binary string       Path to llmkube-metal-agent (default: on PATH, else next to this llmkube)
      --allowlist string          Comma-separated InferenceServices this host serves (agent --inference-service-allowlist; default: all)
      --force                     Replace a com.llmkube.metal-agent LaunchAgent (on Linux, a llmkube-metal-agent.service unit) that join did not write (it is kept in the state directory)
      --host-ip string            IPv4 address the agent registers for the cluster to reach this host (agent --host-ip; default: auto-detect)
      --llama-server string       Path to llama-server, which the agent's llama.cpp runtime needs (default: the agent's search paths, else on PATH)
      --token-lifetime duration   Lifetime of the agent's token; the agent renews it at half (at least 10m) (default 168h0m0s)
      --wait duration             How long to wait for the MetalNode to report Reachable; 0 does not wait (default 3m0s)
```

See also [global flags](#global-flags).

### llmkube metal leave

Stop the Metal agent on this host and remove what join set up

```text
Stop the com.llmkube.metal-agent LaunchAgent and remove its plist and the
agent's kubeconfig and token that 'llmkube metal join' wrote. Engines outlive
the agent, so once it has exited, leave runs the agent's stop-engines to stop
the engines it started and withdraw their endpoints. If that fails, nothing is
removed; run leave again. The agent's ingress identity and model store stay. A
LaunchAgent join did not write (make install-metal-agent, a playbook) is left
running, and its engines with it.

This only cleans up the host: the agent's token stays valid until it expires.
To revoke it and delete the host's objects in the cluster, an admin runs
'llmkube metal remove <name> -n <namespace>'.

On a Linux host, leave stops and disables the llmkube-metal-agent.service
systemd user unit join installed, removes it, and reloads systemd --user. A
unit join did not write is left running.
```

**Usage**

```text
llmkube metal leave [flags]
```

See also [global flags](#global-flags).

### llmkube metal remove

Revoke a Mac and delete its objects

```text
Revoke a Mac's access to the cluster and delete what 'llmkube metal token create'
made for it.

The Mac's ServiceAccount goes first, and the command waits until it is gone:
that revokes every token the Mac holds, including ones it minted for itself.
A token used in the last ~10 seconds can keep working for up to ~10 seconds
more (the API server caches successful authentications). Then the per-Mac
Role, both RoleBindings, the Lease, the join Secret and the MetalNode are
deleted. The shared llmkube-metal-agent Role stays. Objects that are already
gone are skipped, so running it twice is fine.

Only objects labeled inference.llmkube.dev/metal-node=<mac-name> are deleted.
Anything else with one of the Mac's names (another app's Lease, objects
labeled for another Mac, objects applied by hand) is left in place and
listed. --include-unlabeled also deletes unlabeled objects with the Mac's
names, for a Mac set up by hand; objects labeled for another Mac are never
deleted. If the ServiceAccount is left in place, nothing was revoked and the
command fails.

This does not stop the agent on the Mac.
```

**Usage**

```text
llmkube metal remove <mac-name> [flags]
```

**Flags**

```text
      --include-unlabeled   Also delete unlabeled objects with the Mac's names (a Mac whose objects were applied by hand)
  -n, --namespace string    Namespace of the Mac's objects (default: the kubeconfig context's namespace, else default)
```

See also [global flags](#global-flags).

### llmkube metal token create

Create a Mac's identity and print a single-use join string

```text
Create everything a Mac needs to join the cluster and print the join command
to run on that Mac.

In the namespace it creates (or updates) the Mac's ServiceAccount, a per-Mac
Role scoped to the Mac's own objects, RoleBindings to that Role and to the
shared llmkube-metal-agent Role (created from deployment/macos/metal-agent-rbac.yaml
if missing), the Mac's Lease and MetalNode, and a join Secret. The join token
is bound to that Secret, which the Mac deletes when it joins, so the string
works once, and only until it expires (--ttl, 30 minutes by default). It
refuses, before writing anything, when an object with one of the Mac's names
exists and is not labeled for this Mac.

Until it is used or expires, the string is a credential for the Mac's
identity: whoever redeems it can mint the Mac's own tokens. Running this
again for the same Mac kills an unused previous string (within ~10 seconds
if it was just used), but not a string that was already redeemed. If a
string may have leaked, run 'llmkube metal remove <mac>' and then create a
new one. The Mac never sees your credentials.
```

**Usage**

```text
llmkube metal token create <mac-name> [flags]
```

**Examples**

```bash
llmkube metal token create mac-studio
llmkube metal token create mac-studio -n inference --server https://100.64.0.1:6443
```

**Flags**

```text
      --assume-same-server       When --server cannot be reached from here, check the certificate the kubeconfig's server presents instead, assuming --server is the same API server (the Mac still verifies it when it joins)
  -n, --namespace string         Namespace for the Mac's objects (default: the kubeconfig context's namespace, else default)
  -o, --output string            Output format: text or json (default "text")
      --server string            API server URL the Mac connects to (default: the current context's server)
      --tls-server-name string   Name the Mac verifies the API server's certificate against (default: set automatically when the server's address is not in the certificate)
      --ttl duration             How long the join string works (10m to 24h) (default 30m0s)
```

See also [global flags](#global-flags).
